# CardWheel 1.2.0 · MariaDB 직접 연결

추가 API 서버, Docker 컨테이너, 80/443 포트 설정 없이 기존 MariaDB에 JDBC로 직접 연결합니다. Room은 휴대폰 내부 저장소로 계속 사용하고 백업·복원할 때만 DB 연결을 열어 작업 후 닫습니다. 회원가입이나 자동 동기화는 포함하지 않습니다. 같은 DB 계정과 테이블을 사용하는 기기는 같은 카드 백업 한 개를 공유합니다.

## 준비

1. DB 관리자 도구(기존 MariaDB 콘솔, phpMyAdmin, DBeaver 등)에서 `setup.sql`을 실행합니다. 전용 `cardwheel` DB와 `cardwheel_backup` 테이블을 만듭니다. 기존 테이블은 삭제하지 않습니다.
2. `create-account.example.sql`의 비밀번호를 충분히 긴 실제 비밀번호로 바꾸고 실행합니다. 앱 계정에는 이 테이블의 SELECT·INSERT·UPDATE 권한만 부여합니다. 비밀번호를 GitHub나 채팅에 올리지 마세요.
3. 이미 열어 둔 외부 포트가 3306이면 앱 포트에도 3306을 입력합니다. 다른 외부 포트라면 포트포워딩의 외부 포트를 입력합니다. 컨테이너 내부 포트와 외부 접속 포트가 다를 수 있습니다.

이미 API 버전에서 같은 테이블을 만들었다면 테이블 형식은 호환됩니다. 저장된 스냅샷도 그대로 읽을 수 있습니다. 기존 API 주소·접속 키는 DB 접속 정보로 전환할 수 없으므로 앱에서 새로 입력해야 합니다.

## 앱 입력 예

메인 오른쪽 위 **백업**을 누르고 아래 내용을 입력합니다.

| 입력 | 예 |
|---|---|
| DB 서버 주소 | nas.example.com 또는 공개 IP · http://와 https:// 제외 |
| 포트 | 3306 |
| DB 이름 | cardwheel |
| DB 계정 | cardwheel_app |
| DB 비밀번호 | 방금 만든 전용 계정의 비밀번호 |
| 연결 암호화(TLS) | 일반 연결은 끔 · 서버에 TLS가 설정된 경우 켬 |

**연결 확인 및 저장**은 테이블 조회까지 확인하고 접속 정보를 Android Keystore AES-GCM으로 암호화해 저장합니다. 같은 접속 정보에서는 비밀번호 입력을 비워두면 저장된 비밀번호를 사용합니다. 주소·포트·DB 이름·계정이 바뀌면 비밀번호를 다시 입력해야 합니다.

기기의 접속 정보 암호화는 저장된 비밀번호를 보호하는 기능입니다. 네트워크 통신 암호화는 TLS 옵션이 별도로 담당합니다. 비밀번호 필드는 화면 상태/자동 완성 백업에서 제외하며 접속 정보 전체도 시스템 클라우드·기기 전송 백업에서 제외합니다. 새 기기에서는 다시 입력하세요.

## 일반 연결과 TLS

MariaDB 직접 연결은 HTTP/HTTPS가 아닌 DB 프로토콜입니다. NAS 웹 관리 페이지의 HTTPS 설정과 관계없으며 TLS를 켜도 같은 DB 포트를 사용합니다.

- **일반 연결(기본값)**: TLS를 사용하지 않습니다. 공개 인터넷 구간에서 카드 데이터와 SQL은 암호화되지 않습니다.
- **TLS 연결(선택)**: 인증서 체인과 접속 주소, 인증서 유효기간을 검증합니다. 공인 인증서라면 기본 신뢰 인증서를 사용합니다. 자체 서명 인증서나 사설 CA라면 앱에서 PEM 인증서 파일을 선택합니다. 인증서에는 입력한 도메인/IP에 맞는 SAN이 있어야 합니다. 인증서가 없거나 잘못된 경우 일반 연결로 자동 전환하지 않습니다.

TLS가 서버에 켜져 있는지 DB 관리자 도구에서 확인하려면:

```sql
SHOW VARIABLES LIKE 'have_ssl';
```

YES라면 지원하며, TLS 연결 세션에서 `SHOW SESSION STATUS LIKE 'Ssl_cipher';` 결과가 비어 있지 않으면 암호화된 세션입니다. TLS 지원이 없는 서버는 앱 TLS 옵션을 끄고 접속할 수 있습니다.

## 백업·복원

1. **서버에 백업**을 누르면 현재 기기 목록과 교체할 서버 백업 개수를 보여줍니다. 목록을 확인한 뒤 **이 목록으로 서버 백업**을 누릅니다.
2. **서버 백업 불러오기**는 서버 목록을 미리 보여주며, 확인 후 휴대폰의 Room 목록 전체를 교체합니다. 합치기는 하지 않습니다.
3. 서버 백업이 확인 이후 바뀌면 revision 조건으로 저장을 거부합니다. 여러 기기가 처음 동시에 백업해도 하나만 저장됩니다.
4. 기기 데이터가 목록 확인 이후 바뀌면 복원을 중단합니다. 복원은 Room 트랜잭션으로 처리하며 중간 실패 시 원래 목록을 유지합니다.
5. 복원 직전 목록은 기기에 하나 보관하고 **이전 카드로 되돌리기**에서 확인 후 적용할 수 있습니다. 앱 삭제/데이터 초기화 시 이 복구 목록도 사라집니다.

카드는 최대 500개, 백업 JSON은 최대 2MiB입니다. ID·카드사·카드명·상태·금액·모든 날짜·수령/해지 여부·메모를 그대로 보관합니다. 빈 목록도 명시적으로 확인한 후 백업/복원할 수 있지만, 백업이 아예 없는 서버에서는 복원을 진행하지 않습니다. 백업 일시는 저장한 기기의 시간 기준입니다.

조회는 데이터를 변경하지 않습니다. 저장은 prepared statement와 DB 트랜잭션을 사용합니다. 비밀번호는 JDBC URL이나 오류 화면에 출력하지 않습니다. 시간 초과 후에는 저장이 되었을 수 있으므로 서버 목록을 다시 확인한 뒤 재시도하세요.

## 접속 오류 확인

- 연결 실패: 휴대폰의 데이터망에서 서버 주소/외부 포트로 접근 가능한지, NAS 포트포워딩과 DB 컨테이너 포트 매핑을 확인합니다.
- 계정 오류: DB 비밀번호와 원격 접속이 허용된 DB 계정인지 확인합니다. localhost 전용 계정은 외부 휴대폰에서 사용할 수 없습니다.
- 테이블/권한 오류: setup.sql 실행 여부, 입력한 DB 이름, 전용 계정의 세 가지 테이블 권한을 확인합니다.
- TLS 오류: 서버의 TLS 지원과 인증서, SAN의 도메인/IP 일치 여부를 확인합니다. 일반 연결을 의도했다면 앱 TLS 옵션을 끕니다.

기존 Room DB와 applicationId, 앱 버전 **1.2.0(versionCode 9)**은 그대로 유지합니다. 기존 설치를 업데이트할 때는 같은 서명키로 빌드하세요.
