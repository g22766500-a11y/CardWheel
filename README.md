# CardWheel 1.4.0

XML Views + Kotlin + Room 기반 Android 카드 이벤트 관리 앱입니다. versionCode는 16입니다.

## 이번 변경

- 상세 화면에서 **해지 완료**와 **탈회 완료**를 각각 설정합니다. 두 상태가 모두 켜져 있으면 카드에 배지가 두 개 표시됩니다.
- 해지 또는 탈회한 카드는 기존 카드사 색상 위에 반투명 회색 막을 표시합니다. 카드 크기와 상세 보기 동작은 유지됩니다.
- 메인 카드 위의 정렬 버튼에서 최근 등록순, 실적 마감일순, 혜택 지급일순, 혜택 금액 높은순, 카드사 이름순, 카드 이름순, 진행 상태순을 선택할 수 있습니다.
- 선택한 정렬은 앱을 다시 열어도 유지됩니다. 정렬 변경 시 보고 있던 카드를 유지하며, 날짜가 없는 카드는 날짜 정렬에서 마지막에 배치됩니다. 같은 값은 최근 등록순으로 정렬합니다.
- 진행 상태순은 진행 중 → 실적 달성 → 혜택 수령 → 해지 → 탈회 순으로 묶습니다. 해지·탈회 카드는 예상 혜택 합계에서 제외됩니다.

## 기존 데이터와 백업

Room 버전은 2에서 3으로 이전하며 기존 카드/메모/해지 상태는 보존됩니다. 새 탈회 상태는 기본적으로 꺼져 있습니다. 이전 Room 버전 1에서의 업데이트도 지원합니다. 앱을 삭제하거나 데이터를 초기화할 필요가 없습니다.

새 파일 및 MariaDB 백업에는 두 상태가 모두 포함됩니다(백업 schemaVersion 2). 이전 schemaVersion 1 백업도 읽으며 탈회 상태는 꺼진 상태로 복원합니다. **1.3.x 앱에서는 새 백업을 읽을 수 없으므로 백업을 사용하는 다른 기기도 1.4.0으로 업데이트하세요.** DB 테이블 변경은 필요하지 않습니다. 정렬 선택은 기기 설정이며 카드 백업에는 포함하지 않습니다.

## 열기 및 빌드

ZIP을 풀고 Android Studio에서 CardWheel 폴더를 엽니다. JDK 17 이상과 Android SDK 37을 준비한 뒤 Gradle 동기화합니다. 기존 앱을 업데이트하려면 같은 서명키를 사용하세요.

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug assembleRelease
```

파일 백업은 앱 상단 백업 메뉴에서 사용합니다. 원격 백업은 기존 MariaDB에 직접 연결하며 database/README.md 및 SQL 파일을 참고하세요. 추가 API 서버는 필요하지 않습니다.

## 검증 (2026-10-11)

- 디버그 빌드 통과. 기본 릴리즈 최적화 빌드는 이 작업 환경의 리소스 패키징 오류로 최종 완료를 확인하지 못했습니다.
- 기존 기능, 정렬 순서, 독립 배지, Room 1/2 → 3 이전, 백업 이전 형식 호환성을 포함한 테스트 32개 통과.
- lint 분석은 실행했지만 이 작업 환경의 파일 쓰기 판정 문제로 최종 보고서를 생성하지 못했습니다. 릴리즈 배포 전 Android Studio에서 위 빌드 및 검사를 완료하세요. 실제 휴대폰과 사용자의 NAS 연결은 이번 검증에 포함하지 않았습니다.
- design-preview/index.html은 샘플 데이터를 넣어 XML 화면을 렌더링한 라이트/다크 미리보기이며 실제 휴대폰 캡처가 아닙니다.

ZIP에는 소스, 안내, SQL, 미리보기와 테스트가 포함됩니다. SDK, 빌드 캐시, APK, 서명키 및 접속 정보는 포함하지 않습니다.
