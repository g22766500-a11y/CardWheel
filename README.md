# CardWheel 1.3.0 · 파일 백업 + MariaDB 직접 연결

기존 XML Views + Kotlin + Room Android 앱에 MariaDB JDBC 직접 백업·복원을 적용했습니다.
이번 전체 UI 개선 버전은 **1.3.0 / versionCode 13**입니다.

## 시작

디자인은 `design-preview/index.html`에서 라이트·다크 모드로 비교할 수 있습니다.

1. ZIP을 풀고 Android Studio에서 CardWheel 폴더를 엽니다.
2. 파일 백업은 앱 상단 ‘백업’에서 ‘백업 파일 저장’ 또는 ‘백업 파일 불러오기’를 누르면 됩니다. DB 설정이나 저장소 전체 접근 권한은 필요하지 않습니다.
3. 원격 백업을 사용하려면 `database/setup.sql`과 `database/create-account.example.sql`로 기존 MariaDB에 전용 테이블·계정을 준비합니다.
4. 앱 상단 ‘백업’에서 DB 주소·포트(기본 3306)·DB 이름·계정·비밀번호를 입력합니다.
5. 일반 연결 또는 TLS를 선택하고 ‘연결 확인 및 저장’을 누릅니다.

자세한 설정은 **database/README.md**를 확인하세요. 추가 API 서버나 Docker 컨테이너는 필요하지 않습니다.

## 파일 백업 사용법

- ‘백업 파일 저장’을 누르고 Android 파일 선택 화면에서 저장 위치와 파일명을 선택합니다. 클라우드 위치는 해당 저장소 앱이 파일 선택 화면에 제공할 때 사용할 수 있습니다.
- 다른 기기로 파일을 옮긴 후 ‘백업 파일 불러오기’에서 JSON 파일을 선택합니다.
- 카드 수·이름과 백업 날짜를 확인하고 ‘이 목록으로 기기 복원’을 눌러 적용합니다. 병합이 아니라 전체 교체이며 기존 목록은 ‘이전 카드로 되돌리기’로 복구할 수 있습니다.
- 선택 취소는 카드 데이터를 바꾸지 않습니다. 잘못된 형식, 중복 ID, 잘못된 값, 손상된 UTF-8, 뒤에 붙은 내용, 500개·2MiB를 초과하는 파일을 거부합니다.
- 일반 JSON 파일이며 암호화되지 않습니다. 카드 정보와 메모는 포함하고 MariaDB 계정·비밀번호·인증서는 포함하지 않습니다. DB 설정 없이 오프라인에서 사용할 수 있습니다.
- 파일 형식은 schemaVersion 1이며 카드의 모든 Room 필드를 보존합니다. 앱 내부 DB schema version은 2를 유지합니다.
- 저장 위치에서 접근 권한이 없어지거나 클라우드 업로드가 실패하면 파일 작업이 실패할 수 있습니다. 저장 완료는 파일 제공자에 쓰기를 마쳤다는 뜻이며 클라우드 업로드 완료까지 보장하지 않습니다.

## 이번 변경

- 1.3.0에서는 스위치 외곽선을 없애고 고정 24dp 흰 손잡이를 유지했습니다. 파란 포인트와 중립 배경, 테두리 없는 정보 섹션, 일관된 버튼·입력창·툴바 스타일로 전체 화면을 정리했습니다.
- 메인의 요약 정보와 페이지 표시, 빈 상태 아이콘을 정리했습니다. 카드 ViewPager의 크기·FAB 예약 영역·스와이프 처리는 유지합니다.
- 상세 화면의 일정을 좌우 행으로 구성하고 상태를 배지로 표시했습니다. 등록 화면은 카드 정보·금액·일정·메모 섹션으로 구분하고 날짜 선택 버튼에 캘린더 아이콘을 넣었습니다.
- 백업 화면은 파일 백업을 먼저 보여주며, 서버 연결 설정을 펼치고 접을 수 있습니다. 펼침 상태는 화면 회전 후 유지합니다.

- OFF에서 손잡이를 줄이는 기본 애니메이션을 고정 벡터 손잡이로 교체했습니다. 흰 원의 지름은 OFF/ON 모두 24dp이고 손잡이의 좌우 이동은 유지합니다.


- Material 기본 보라색이 남던 스위치 OFF 배경과 진행률 트랙의 colorSurfaceVariant를 라이트/다크 회색으로 명시하고, 관련 컨테이너·보조 색상도 앱 팔레트로 통일했습니다.

- 파일 백업·목록 미리보기·확인 후 복원·되돌리기를 추가했습니다.

- MariaDB JDBC 직접 연결로 원격 백업·복원을 제공합니다. 연결은 백그라운드에서 열고 작업 후 닫습니다.
- 일반 연결을 기본값으로 두고 TLS를 선택할 수 있습니다. 일반 연결의 공개 인터넷 통신은 암호화되지 않습니다.
- TLS는 인증서 체인·호스트·유효기간을 확인하고 자체 서명/사설 CA용 PEM 인증서를 선택할 수 있습니다. 실패 시 일반 연결로 자동 전환하지 않습니다.
- DB 비밀번호와 접속 정보는 Android Keystore AES-GCM으로 암호화해 저장하며 시스템 백업에서 제외합니다. 비밀번호를 JDBC URL/오류/연결 정보 문자열에 출력하지 않습니다.
- 목록 확인 후 서버 백업, 목록 확인 후 기기 복원, 복원 전 목록으로 되돌리기를 유지합니다.
- 서버 revision 조건과 DB 트랜잭션으로 동시 덮어쓰기를 방지합니다. 로컬 복원도 Room 트랜잭션으로 처리합니다.
- 원래 Room schema version=2와 applicationId=com.example.cardwheel, DB 파일명=cardwheel_database를 유지합니다. 기존 카드의 모든 컬럼을 보존합니다.

가로형 카드/IC 칩, 카드사 드롭다운·배경색, 고정 카드 크기, FAB 전용 영역, 스와이프 햅틱, 날짜 선택, 상세 수정·삭제, 기본 검증 기능도 유지합니다.

## 빌드와 검증

원래 프로젝트의 SDK Platform 37.0, Build Tools 36.0.0, Gradle 9.6.0, AGP 9.4.1, JDK 25를 유지합니다. 새 드라이버는 MariaDB Connector/J 3.5.10이며 minSdk 24를 위해 Java 라이브러리 desugaring을 활성화했습니다.

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug assembleRelease
```

검증 결과 (2026-10-05):

- 디버그·릴리즈 빌드 통과. 릴리즈 APK는 서명 전 파일입니다.
- Android 단위/화면/Room 회귀 테스트 27개 통과, 실패 0.
- lintDebug 오류 0, 경고 36개. 남은 경고는 의존성 업데이트·KTX/레이아웃/문자열 등 개선 제안입니다.
- 임시 MariaDB 11.4.9와 앱의 JVM 클래스/JDBC 드라이버로 일반 연결, 모든 필드 보존, 이전 revision 거부, 동시 저장, 잘못된 계정, PEM 인증서를 검증한 TLS, 신뢰하지 않는 TLS 인증서 거부, 빈 백업 등 8개 항목 통과.
- 두 APK의 TLS 서비스 프로바이더 리소스 포함 확인.
- 별도 Native 렌더링으로 샘플 데이터를 넣은 XML 화면 14장(라이트/다크, 스크롤 아래쪽 포함)을 생성하고 배치를 확인했습니다. 실제 휴대폰 캡처는 아닙니다.

Robolectric 테스트는 Android 15(API 35) 환경입니다. 실제 Android 기기/사용자의 공개 NAS 서버 연결은 아직 확인하지 않았습니다. 작업 환경에서 Android 도구 캐시의 실행 제한을 피하기 위해 동일한 공식 AAPT2 실행 파일을 작업 폴더로 복사해 검증했으며 이 임시 경로는 프로젝트에 포함하지 않았습니다.

기존 앱을 업데이트하려면 같은 서명키로 빌드하세요. 앱 삭제/데이터 초기화 시 기기 Room 데이터와 복원 전 목록은 사라집니다.

ZIP에는 Android Studio 프로젝트, DB 준비 SQL·안내와 테스트 소스가 들어 있습니다. 빌드 캐시·SDK·서명키·실제 접속 정보·API 서버 프로그램은 포함하지 않습니다.
